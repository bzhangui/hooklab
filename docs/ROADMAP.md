# HookLab 开发路线与范围基线

本文件区分“申报前已有基础”和“申报后计划新增”，防止把现有 MVP 与本次开发成果混为一谈。里程碑按能力门禁推进，不以堆积代码行数或拆分无意义提交为目标；每个提交应对应一个可审查的工程变化。

通过预答辩后，开发期将按 issue/里程碑保留完整历史，规划形成不少于 100 个有意义、可审查、可独立回退的提交，以满足赛事启动支持的过程要求；不使用空提交，也不把同一个原子改动机械拆分来凑数量。实际口径以赛事组后续通知为准。

## M0：公开 MVP（已完成）

- 纯 MoonBit SHA-256/HMAC-SHA256 与官方向量。
- GitHub、Stripe、飞书、通用 HMAC 验签和时间窗。
- 内存幂等、JSON 路由、递归脱敏、重试/死信决策。
- CLI、离线 HTML/JSON 报告、四套示例。
- 22 项测试在 JS、Wasm、Wasm-GC、Native 通过。

M0 用于证明方向可行，不等同于生产就绪版本。内存幂等、UTF-8 文本请求模型和 Node 专用网络 I/O 是明确的现有边界。

## M1：安全内核强化（P0）

- 将请求体升级为字节优先模型，支持 Unicode 与任意二进制负载。
- 实现增量/流式 SHA-256 与 HMAC，控制大负载内存占用。
- 设计 provider adapter 契约，增加密钥轮换和多签名策略。
- 增加 payload/header 大小限制、时间策略验证和稳定错误上下文。
- 加入属性测试、模糊输入语料和跨目标一致性测试。

退出条件：官方向量、篡改、格式、编码、边界长度和密钥轮换测试全部通过，公共 API 有生成接口和迁移说明。

## M2：持久化可靠交付（P1）

- 定义 `IdempotencyStore`、`DeliveryStore`、`Clock`、`Transport` 窄接口。
- 实现文件 WAL/快照恢复参考后端；给数据库后端提供事务语义说明。
- 实现 queued/in-flight/succeeded/dead-letter 状态机、租约、确认和恢复。
- 增加确定性调度器、退避抖动策略、重试分类和手工死信恢复。
- 通过崩溃点注入证明恢复后不丢任务，并依靠幂等避免重复副作用。

退出条件：进程在写入、领取、投递、确认各阶段退出后均可恢复；同一 delivery ID 的副作用次数符合约定。

## M3：完整用户体验（P1）

- 提供本地入站 HTTP 接收器与带 allowlist 的出站投递器。
- 提供声明式配置、配置校验、`doctor` 和清晰的诊断建议。
- 将核心编译到 Wasm，制作完全离线的浏览器验签/路由/脱敏诊断台。
- 支持从 cURL/HAR/脱敏 fixture 导入，导出可分享但不含密钥的报告。
- 补齐 Linux/macOS/Windows 使用路径和端到端演示。

退出条件：新用户按照 README 可在 5 分钟内运行示例；浏览器与 CLI 对同一 fixture 给出一致结论。

## M4：可观测性与生态扩展（P2）

- 指标、结构化事件、trace ID 与敏感字段审计。
- provider/storage/transport 扩展模板和第三方实现兼容测试套件。
- 性能基准、负载测试和资源上限说明。
- 开发历程、AI 协作记录、架构决策记录（ADR）与完整验收报告。

## 明确不做

- 不提供任意脚本执行或把 payload 字段拼接为目标 URL。
- 不承担 TLS 证书、云端密钥托管、用户计费和多租户隔离平台职责。
- 不承诺“恰好一次”网络投递；采用至少一次投递加消费端幂等，明确故障语义。
