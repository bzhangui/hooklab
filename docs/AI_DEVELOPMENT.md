# AI/智能体协作与开发可解释性

## 分工原则

- 参赛者/维护者确定实际问题、范围、优先级、安全边界和最终验收。
- AI/智能体用于检索官方资料、拆解任务、生成候选实现/测试、运行工具、定位失败和检查文档一致性。
- 编译器、测试、官方向量、可复现示例和人工工程判断共同充当验证器；AI 输出本身不是正确性证据。

## 当前项目中的使用

1. 将 Webhook 问题拆为 crypto、provider、idempotency、routing、redaction、retry、report 等窄包。
2. 生成纯 MoonBit SHA-256/HMAC 候选实现，并用标准向量和四目标测试验证。
3. 对照 GitHub、Stripe、飞书官方文档复核签名输入和时间策略。
4. 通过负向测试发现并修复非法十六进制摘要、非法时间戳降级和 HTML/JSON 转义边界。
5. 根据本地和 GitHub Actions 日志定位工具链版本差异，保持远程 CI 可执行。

## 后续记录要求

每个重要里程碑记录：问题与证据、候选方案、AI 建议、维护者选择、拒绝方案、验证命令、风险和后续事项。重大架构取舍写入 ADR；不得记录密钥、真实客户 payload、个人隐私或未经授权的外部系统信息。

## 质量防线

- 需求与代码建立验收矩阵，不使用“看起来能运行”作为完成标准。
- 安全协议优先采用供应商官方资料和标准测试向量。
- 生成代码必须格式化、无警告检查、测试和构建；高风险路径增加负向/故障测试。
- 保留清晰提交历史；不为满足提交次数制造空提交或把一个原子变化机械拆碎。
