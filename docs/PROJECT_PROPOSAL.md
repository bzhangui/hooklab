# HookLab 项目申报书

## 1. 项目目标与应用场景

Webhook 已广泛用于支付、代码托管、协同办公和自动化系统，但工程团队仍需反复处理“原始请求体验签失败、旧请求被重放、同一事件重复产生副作用、下游临时故障、调试日志泄露密钥”等问题。HookLab 拟合成一个 **MoonBit 原生、跨平台、可嵌入的 Webhook 安全与可靠性交付核心**：以统一事件模型连接验签、防重放、幂等、路由、脱敏、重试、死信和离线诊断，使开发者与 AI 代理都能用确定的命令复现问题并获得机器可读结论。目标用户是维护第三方回调的个人开发者、后端团队、自动化平台与 MoonBit 应用作者。

## 2. 现有基础与本次开发范围

当前仓库已完成可运行 MVP：纯 MoonBit SHA-256/HMAC-SHA256、常量时间比较，GitHub/Stripe/飞书/通用 HMAC 验签，时间窗与 delivery ID 防重放，JSON 路由和递归脱敏，指数退避/死信决策，安全 replay fixture，Node CLI 与单文件离线报告；22 项测试分别在 JS、Wasm、Wasm-GC、Native 通过，GitHub Actions 为绿色。

本次计划在 MVP 上新增生产级能力：① 字节优先与流式摘要，避免文本转换破坏签名；② 可替换 provider adapter 与密钥轮换；③ 持久化幂等/WAL 任务队列、调度器和死信恢复；④ 入站接收器与受控出站投递；⑤ 编译到 Wasm 的浏览器诊断台；⑥ 指标、结构化追踪、基准与属性/模糊测试。功能边界不包括通用 API 网关、任意脚本执行、多租户计费平台和密钥托管服务。

## 3. 交付物、使用流程与验收

- **代码**：可复用 MoonBit packages、`hooklab` CLI、浏览器诊断台和持久化交付示例。
- **核心流程**：导入原始 body/headers → 选择 provider 与密钥 → 验签和时间窗校验 → 原子幂等 → 规则路由 → 投递/退避/死信 → 输出已脱敏诊断。
- **测试**：官方协议向量、篡改/过期/未来时间、重复事件、崩溃恢复、路由和脱敏边界；覆盖四个编译目标，并增加属性测试、模糊测试、集成测试和基准。
- **文档**：快速开始、协议契约、架构与威胁模型、部署/扩展指南、演示脚本、开发历程和验收矩阵。
- **完成判据**：全目标无警告构建；关键安全路径和恢复路径可由单条命令复现；同一持久化事件不重复产生副作用；报告不含配置的敏感值；CI 自动执行声明的测试。

## 4. 技术路线与 MoonBit/AI 使用

系统分为 `core → crypto/providers → engine → pipeline → report/CLI/Web`。协议适配器只负责认证输入，幂等在认证后执行，原始事件用于投递，脱敏副本用于观察；重试由确定性状态机驱动，持久化层通过窄接口替换。MoonBit 的代数数据类型表达可穷举错误与投递决策，包系统隔离安全边界，同一核心编译到 Native/JS/Wasm，生成接口文件用于审查 API 演进。

AI/智能体用于需求拆分、候选架构、代码与测试生成、官方协议交叉核对、失败日志定位和文档一致性检查；每个候选变更必须经过 `moon fmt/check/test/build`、官方测试向量和可复现命令验证。维护者负责目标、范围、安全取舍、验收与最终提交，避免把无法验证的生成结果直接合入。

## 5. 风险与应对

| 风险 | 缓解措施 |
|---|---|
| 供应商协议差异或升级 | 每个 provider 独立适配；记录官方依据和固定向量；版本化契约 |
| 文本编码/代理改写导致验签错误 | 字节优先 API；验签前禁止解析；保留原始证据摘要 |
| 并发下重复副作用或进程崩溃丢任务 | 数据库唯一约束、WAL、租约/确认状态机与故障注入测试 |
| replay 引发 SSRF 或数据外泄 | 默认禁用任意生产目标；allowlist、超时、大小限制、脱敏和显式授权 |
| 多目标 I/O 能力不同 | 纯核心保持可移植；I/O 使用窄适配层；CI 对四目标持续验证 |
| 范围过大 | 以安全闭环为 P0，持久化为 P1，Web UI/插件为 P2；按验收门禁逐级交付 |

## 6. 相关实践、原创性与个人匹配度

协议实现依据 GitHub、Stripe、飞书官方验签文档和 SHA/HMAC 标准测试向量，并借鉴成熟 Webhook 系统中“签名认证—幂等—队列—重试—死信—可观测性”的工程分层，但不复制其源码。当前核心无第三方运行时依赖，来源与协议情况见 `THIRD_PARTY_NOTICES.md`。本项目由参赛者以 MoonBit 原生实现，不是已有项目的移植；当前跨目标核心、CLI、测试与 CI 构成技术可行性证明。个人更详细的教育/工作经历由参赛者在报名问卷中如实补充。

## 7. 预期价值

HookLab 的差异化不是再做一个在线请求收集页面，而是提供可嵌入、可验证、跨端一致的可靠性交付内核：生产服务可使用同一套规则，浏览器可离线诊断，AI 代理可依赖稳定错误码自动修复配置。项目可成为 MoonBit 生态中 Webhook、任务队列和事件驱动应用的公共基础组件，并通过 provider、storage、transport 三类边界长期演进。

> 移植声明：不适用。本项目为原创 MoonBit 项目，不存在原项目或原项目链接；本次开发是在公开 MVP 基线上继续扩展生产级能力。
