THE DELIVERY PATH

可靠性不靠“发送成功”
这一个状态。

一次完整交付需要能判断请求是否可信，能找回失败任务，也能解释消费者最终收到什么。

01

先确认事件有效

接入侧验签，按契约校验正文。无效请求在写入与投递之前被拒绝。

02

再记录每次尝试

事件和任务持久化后由 Worker 投递；失败重试与尝试历史留有迹可查。

03

最后交给消费者去重

交付遵循至少一次语义；接收端按交付 ID 去重，避免重复业务效果。
